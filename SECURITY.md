# Security

## Reporting a vulnerability

Report privately via [GitHub Security Advisories](https://github.com/hidaroz/project-medusa/security/advisories/new).
Please don't open a public issue for anything exploitable.

Expect an acknowledgement within a week. This is coursework turned personal
project, not a funded one — there's no bounty and no guaranteed patch window.

## Read this before you run anything here

**`medusa-cli` is an offensive tool.** It drives nmap, SQLMap and Metasploit
against whatever target you point it at, and it decides its own next move in an
OODA loop rather than asking you per-step. Pointing it at infrastructure you do
not own or have written authorisation to test is a crime in most jurisdictions.
The autonomy is the interesting part of the project and it is also the part that
will get you in trouble; there is no confirmation prompt between the planner and
the exploit.

**`lab-environment/` is vulnerable on purpose.** Eight Dockerised services — an
EHR web app, an Express API, FTP, SSH, MySQL, a log collector, a workstation —
carrying weak credentials, outdated dependencies and reachable SQL injection
sinks. They exist so the agent has something legal to attack. Do not deploy them
anywhere reachable from a network you don't control, and do not copy patterns out
of them into real code.

Because those findings are intentional, `lab-environment/` and `archive/` are
excluded from CodeQL by path in `.github/workflows/codeql.yml` rather than
scanned and dismissed one alert at a time. The exclusion is written in one file
you can read instead of scattered across a hundred dismissal reasons.

## Known gaps

**Container state was committed to this public repo, including TLS private keys.**
Through commit `6714fe3`, `project-medusa/lab-environment/dev-data/` held 213
files of MySQL and OpenLDAP runtime state — roughly 200 MB — among them
`server-key.pem`, `ca-key.pem`, `client-key.pem` and `private_key.pem`, plus
`mysql.ibd` and seven binlogs.

Those keys were generated by the MySQL container on first boot. They authenticate
one throwaway lab on one laptop and protect nothing else, so this is not a
credential compromise and there is nothing to rotate. They still had no business
being in a public repository, and the honest summary is that a `.gitignore` entry
was missing for eight months.

They are removed from HEAD and ignored going forward. **They remain in git
history.** Rewriting the history of a public repo that is cited by a thesis, in
order to scrub keys that guard a local docker-compose lab, trades a real
availability cost against a theoretical confidentiality gain. That trade wasn't
worth it. `.gitleaks.toml` allowlists the path so the secret scan stays useful
instead of permanently red on a known, documented finding.

**Python dependencies are pinned at December 2023 versions.** `medusa-cli` pins
roughly twenty packages with `==`, several of which now carry advisories
(`jinja2`, `flask-cors`, `pydantic`). Dependabot security updates are enabled;
routine version updates are disabled, because the test suite has never run in CI
and unverifiable bumps to a tool that shells out to Metasploit are not an
improvement.

**The web dashboard has no authentication.** `medusa-webapp` is a static export
that reads local run artifacts. It assumes it is served to one operator on one
machine. Do not host it.
